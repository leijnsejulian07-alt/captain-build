# Captain OSS audit — 2026-09-05

## Scope
Daily scan for reusable subsystems that strengthen Captain without creating a second control-plane.

## Shortlist
### Shofer (Apache-2.0)
Useful patterns: deterministic declarative multi-agent workflows, live execution topology, hard task/session cost caps, worktree-scoped OS sandboxing, semantic git-history search.
Decision: ADAPT PATTERNS, do not install yet. Linux sandbox primitives are not a direct Windows fit; orchestration must remain behind Captain.

### QodeX (Apache-2.0)
Useful patterns: Tree-sitter impact analysis, Docker-backed command execution, Playwright verification, dev-server/background-job lifecycle, multi-file atomic edits.
Decision: HIGH-VALUE ADAPTER CANDIDATE after isolation P0. Prefer selective reuse of code-intelligence/browser verification ideas over adopting its agent loop.

### Heroi (Tauri v2 / React / Rust)
Useful patterns: lightweight worktree manager, PTY terminal, live git diff/stage UI, IDE launch controls.
Decision: UX/implementation reference for Captain Builder pane. No need to import its orchestration layer.

### Bothread (MIT)
Useful patterns: file-claim collision prevention, durable local notes/task board, agent hand-off.
Decision: ADAPT collision-avoidance ideas only if Captain later supports multiple builder workers in one repo.

### Rookery
Useful patterns: durable resident jobs, per-worker transcript/diff/terminal, ranked attention queue.
Decision: UX reference only. Do not adopt its long-lived daemon because Captain already has the single primary control-plane.

## Current priority
Do not integrate any candidate before Project State isolation is green across chat, memory/context, files, builder/preview and update surfaces.
