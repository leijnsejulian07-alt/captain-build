# Captain OSS capability audit — 2026-09-10

Purpose: identify reusable components/patterns that improve Captain without replacing its single control-plane or weakening `chat_id + project_id + repo_scope + state_epoch` authority.

## HyprDesk

- Source: https://github.com/HyprDesk/hyprdesk
- License: MIT.
- Capability: desktop orchestration of coding agents with git-worktree isolation, persistent sessions, PTY-driven agents and a Tauri v2 IDE surface.
- Fit: useful reference for Captain's builder pane, especially worktree/session UX and merge-back. Captain must retain routing, authority, memory and permission ownership; do not import its router-leader as a second control-plane.
- Risk/cost: very young project and low adoption; real PTYs/agents mean green typechecks alone are insufficient. Treat as design reference first, not trusted runtime dependency.
- Decision: WATCH / ADAPT PATTERNS, not direct integration yet.

## devsandbox

- Source: https://github.com/zekker6/devsandbox
- Capability: per-project agent sandboxing; protects SSH/cloud credentials, `.env` files and sibling projects; supports worktree isolation and network logging/filtering.
- Fit: strong candidate to study behind a future backend-neutral `SandboxAdapter`, because its security boundary addresses exactly the class of builder/agent leakage Captain must prevent.
- Platform/resource note: bubblewrap on Linux, Docker or libkrun elsewhere. Windows laptop suitability and resource cost require local benchmarking before adoption.
- Decision: EVALUATE ADAPTER FIT; never blindly install or execute. Verify license/security/dependency posture before any integration.

## MCP Tasks Extension / 2026 direction

- Official source: https://tasks.extensions.modelcontextprotocol.io/seps/2663-tasks-extension
- Tasks are an official extension with `tasks/get`, `tasks/update`, and `tasks/cancel`; task creation is per-request/server-directed.
- The old unscoped `tasks/list` was removed because it could not be scoped safely in the stateless model.
- Fit: validates Captain's fail-closed scoped-job direction. If Captain exposes MCP-compatible async jobs, ownership must remain Captain-controlled and project/epoch-bound rather than adding a globally enumerable task plane.
- Decision: ALIGN SEMANTICS where useful; do not replace Captain's persistent job store/control-plane.

## Priority from this audit

1. Finish canonical `ProjectAuthority` runtime adoption first.
2. Reconcile it locally into Project Memory/context and run stale/future epoch + normal-chat regressions.
3. Then evaluate devsandbox-style sandbox boundaries and HyprDesk-style worktree/session UX behind Captain-owned adapters.
