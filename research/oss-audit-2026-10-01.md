# Captain OSS audit — 2026-10-01

Scope: builder/preview, sandboxing, permissions, connector UX. This is research/parking only; no third-party code was installed or executed.

## Candidates

### LaunchKit AI — reference only
- MIT; prompt-to-app loop with Inngest + E2B + preview artifacts.
- Useful architecture reference for preview artifact lifecycle and CI gates.
- Poor direct fit for laptop-first Captain because it assumes hosted dependencies (E2B, Clerk, Prisma/Postgres, Inngest) and introduces orchestration Captain already owns.
- Decision: do not integrate wholesale. Borrow testable preview/artifact patterns only.

### DCode — reference/adapt selective UI contracts
- MIT; Electron/React desktop coding agent.
- Clean split: renderer -> preload bridge -> desktop capabilities; runtime-neutral contracts and agent-core.
- Permission modes and explicit warning that path checks are not OS isolation align with Captain's fail-closed model.
- Decision: inspect UI/contract patterns later; do not add its agent/router as a second control-plane.

### Kilntainers — sandbox backend candidate, pending deeper audit
- MIT according to upstream/community release.
- Supports local Docker/Podman plus optional micro-VM/WASM backends; per-agent ephemeral isolation.
- Potential fit as a replaceable execution adapter behind Captain ownership gates.
- Risks: Docker resource cost on laptop; MCP surface must not become an authorization boundary; needs upstream activity/security/dependency review before any install.
- Decision: shortlist for adapter spike only after local acceptance suite is green.

### Vercel coding-agent-template — connector UX reference only
- Demonstrates connectors tab, MCP server setup and OAuth secret encryption.
- Hosted/Vercel architecture and agent ownership overlap make direct integration unattractive.
- Decision: use as UX/reference material for Captain Settings Installed/Connected/Enabled/Ready/Permissions states, not as subsystem.

## Integration invariants
Any builder/sandbox adapter remains subordinate to Captain. Before create/resume/result-accept/preview/file/git/tool side effects, Captain must validate current chat_id + project_id + repo_scope + Project State epoch and per-action permission. Connector/MCP authentication does not replace this authorization gate. No secrets in logs, persisted notices, provenance records, or Git.
