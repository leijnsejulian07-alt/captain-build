# Captain OSS audit — 2026-09-06

## Scope
Daily scan for reusable subsystems that strengthen Captain without creating a second control-plane or weakening project/repo/epoch isolation.

## New shortlist

### Agetor (MIT)
Useful patterns: local-first task board, one worktree per agent task, structured approvals/questions, streamed run output, per-task approval scope, localhost token gating.
Fit: GOOD UX/orchestration reference for Captain Builder and task UX.
Caution: agents run with full shell privileges and Windows is currently untested.
Decision: ADAPT UI/approval/task-session patterns only; do not use as Captain's control-plane or sandbox.

### AWO — Agent Worktree Orchestrator (MIT)
Useful patterns: deterministic verification, explicit safety invariants, artifact-backed reruns, no auto-push/merge, sandbox-bounded mutation.
Fit: HIGH-VALUE reference for Captain plan→build→verify→review acceptance receipts.
Decision: ADAPT verification/artifact contracts rather than adding another orchestrator.

### BiomeLab
Useful patterns: worktree dashboard with per-agent state and optional Docker sandbox where each worktree gets isolated filesystem, Docker daemon and network.
Fit: useful Builder isolation reference.
Caution: Docker-level isolation may be heavy for this laptop and must remain optional.
Decision: ADAPT runtime-isolation concepts; prefer lighter per-session slots first.

### Klaussy Desktop
Useful patterns: live file tree/editor, worktree-per-agent, commit-time review gate, CI log debugging, inline CI annotations, broad agent backend support.
Fit: strong UX reference for Captain's Builder pane and GitHub review loop.
Decision: ADAPT Builder/CI review interaction patterns; do not replace Captain.

## Architecture conclusions
1. Worktrees remain necessary but insufficient: process, port, preview, environment and service state need explicit per-session isolation.
2. Deterministic verification receipts are preferable to trusting agent self-report.
3. Approval state should be task/session scoped, never global.
4. Captain remains the only primary control-plane; external components are adapters/subsystems.
5. No candidate warrants direct installation before chat/memory/context epoch walls are green locally.

## Security / resource notes
No third-party code was installed or executed. No paid service was activated. No secrets or machine-specific credentials were written to GitHub.
