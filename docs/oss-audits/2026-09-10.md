# Captain OSS capability audit — 2026-09-10

Purpose: identify reusable subsystems that add capability without creating a second Captain control-plane. No third-party code was installed or executed during this audit.

## OpenHands Agent SDK / Canvas
- Status: promising adapter/reference candidate, not a replacement orchestrator.
- Evidence: active upstream repositories as of 2026-09-09; core/SDK are MIT-licensed. Current architecture separates Canvas, Agent Server/SDK, TypeScript client and automation service.
- Captain fit: strong for repo-aware coding loops, agent-server adapters, event/workspace concepts and builder-pane UX patterns.
- Integration rule: Captain remains the sole user-facing orchestrator/router. Prefer a narrow OpenHands SDK/agent-server adapter behind Open Builder; do not import its automation/router layer as a competing control-plane.
- Resource/security: container/backend execution can be heavy on a laptop; evaluate local CPU/RAM and sandbox boundaries before enabling.
- Priority: HIGH for a later controlled spike after current isolation/settings work is locally reconciled.

## Nightona (Daytona community continuation)
- Status: watchlist, not ready for direct Captain integration.
- Evidence: continuation of Daytona's last open AGPL-3.0 release after upstream core moved private in June 2026; project states it is still in bootstrap/rebrand phase.
- Captain fit: useful sandbox/workspace concepts, but AGPL obligations, bootstrap maturity and Docker/Kubernetes footprint reduce laptop fit.
- Priority: WATCH. Re-evaluate maintenance/security activity before any adapter work.

## MCP 2026-07-28 authorization direction
- Status: architecture input, not a dependency decision.
- Evidence: current MCP spec hardens OAuth issuer validation, binds credentials to their issuer, and deprecates Dynamic Client Registration in favor of Client ID Metadata Documents; Tasks are now an extension rather than unscoped core behavior.
- Captain fit: reinforces canonical Settings + explicit provider adapters, issuer-bound auth, migration/version health, scoped tasks and no invented auth.
- Priority: HIGH. Apply these constraints to Captain connector adapters as they are implemented.

## Community signal: Codeman / self-hosted agent control centers
- Status: UX/reference candidate only.
- Signal: recent self-hosted community projects emphasize persistent sessions, browser-visible terminals and per-project hardened containers. Community feedback around similar control centers specifically calls out per-agent/folder/tool permissions, logs and a kill switch.
- Captain fit: supports the existing direction for builder-pane session visibility, scoped permissions, observability and explicit stop/rollback controls.
- Priority: MEDIUM as UX/reference material; no direct integration until repository/license/security review is complete.

## Decision this audit
Continue building Captain's connector action boundary now. After local reconciliation, run a focused OpenHands SDK adapter spike behind Open Builder and benchmark laptop cost. Do not adopt Nightona yet. Keep MCP 2026-07-28 auth/version migration rules as connector acceptance criteria.
