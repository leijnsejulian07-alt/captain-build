# Captain OSS scout — 2026-09-15

Scope: fresh scan across GitHub, official docs, developer/community material and Reddit-indexed discussions. Only candidates that can sit behind Captain's existing control-plane are considered. No third-party code was installed or executed.

## Inspect AI — high-value evaluation adapter candidate
- Source: https://github.com/UKGovernmentBEIS/inspect_ai
- Official docs: https://inspect.aisi.org.uk/
- License: MIT per upstream repository metadata/readme.
- Capability: mature LLM/agent evaluation framework with datasets, solvers, scorers, transcripts/log viewer and a large public eval ecosystem. Its Agent Bridge can wrap third-party Python agents or CLI agents in sandboxes rather than requiring Captain to adopt another orchestration control-plane.
- Particularly relevant: sandbox_agent_bridge can withhold host-side web/code/MCP capabilities unless explicitly granted, supports approval policies before tool calls reach the bridged agent, and records model traffic/transcripts. Current docs also describe checkpointing for long-running evals.
- Fit: strong optional evaluation subsystem behind Captain. Captain should export scoped, synthetic/regression scenarios into Inspect and consume score/trace results; Captain remains authoritative for chat_id/project_id/repo_scope/epoch, provider routing, approvals and job state.
- Resource cost: Python framework itself is reasonable; actual eval cost depends on model/sandbox choice. Default Captain smoke/regression suites should remain local/deterministic, with Inspect used for richer opt-in capability/safety evals.
- Decision: prioritize a narrow adapter/proof-of-concept after local B310 reconciliation. Do not route normal Captain traffic through Inspect and do not let its model bridge become Captain's primary router.

## Docling — high-value document-ingest adapter candidate
- Source: https://github.com/docling-project/docling
- Project: https://github.com/docling-project
- License: MIT for the codebase; model licenses must still be checked individually.
- Capability: local parsing of PDF, DOCX, PPTX, XLSX, HTML, images and audio into a structured DoclingDocument with Markdown/JSON export; stronger PDF layout/table/formula handling than a plain text extractor.
- Fit: useful research/file-ingest subsystem behind Captain, especially for evidence-preserving document research. Parsed chunks must inherit Captain source/provenance metadata plus exact project/repo/epoch scope before entering context or memory.
- Resource cost: potentially heavier than simple text conversion, especially advanced PDF/model pipelines. Prefer slim/local configuration and benchmark CPU/RAM/startup latency on B310 before enabling by default.
- Decision: promising optional parser for difficult documents, not a mandatory daemon.

## Microsoft MarkItDown — lightweight ingest candidate
- Source: https://github.com/microsoft/markitdown
- Capability: lightweight conversion of many office/document/media formats to LLM-oriented Markdown. Upstream explicitly warns that conversion performs I/O with the privileges of the current process and recommends narrow conversion functions/sanitized untrusted inputs.
- Fit: good fast-path before heavier Docling. Run behind Captain file/sandbox permissions, never as an unrestricted MCP/file authority. Preserve the original source digest and provenance alongside converted text.
- Decision: evaluate as a lightweight local fast-path; fall back to Docling only when structure/layout quality requires it. No install yet.

## Community/reliability takeaway
- Recent Reddit-indexed developer examples reinforce patterns Captain is already moving toward: explicit Test Connection before depending on an external provider, local fallback when optional AI is unavailable, idempotent event ingestion, audit/simulation modes, and separate state/keyspaces to avoid cross-installation leaks.
- These are design signals, not dependencies. Captain should keep one control-plane and exact project/repo/epoch ownership instead of importing another app's state model.

## Priority outcome
1. Keep the new deterministic integrated epoch/isolation acceptance test in Captain's own CI as the cheap always-on gate.
2. Once B310 is reachable and the fallback is reconciled, evaluate Inspect AI as an optional richer eval runner behind Captain, with no routing authority.
3. Prototype a two-tier document ingest adapter: MarkItDown fast-path, Docling structured fallback, both constrained by Captain scope/provenance/security gates.
4. No candidate is installed or enabled until local resource/security tests are green.
