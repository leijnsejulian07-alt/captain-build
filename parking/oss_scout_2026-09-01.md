# Captain OSS scout — 2026-09-01

Parking-only research while the live Captain laptop filesystem is unreachable. No third-party code was installed or executed.

## Promising candidates

### PLUR
- Capability: open, portable typed agent-memory/engram format with local implementations and MCP/Python/TypeScript support.
- License: specification is Apache-2.0.
- Fit: medium-high as a serialization/interchange layer for Captain Memory, not as a second authoritative memory service. Captain must remain the persistent source of truth and project/chat/repo scoping must be added to any imported/exported engram contract.
- Resource cost: low if only the format/adapters are reused; local retrieval/reranking needs separate laptop measurement.
- Decision: evaluate the schema and retrieval benchmark methodology; do not adopt a parallel memory authority.
- Source: https://plur.ai/

### PI-Desktop
- Capability: local-first coding-agent desktop with sandboxed Electron renderer, Rust host core, SQLite persistence, workspace permissions, browser preview, terminal, diff review, extensions/MCP/skills/subagents and context checkpoints.
- Fit: high as architecture/reference material for Captain's interactive builder pane and narrow renderer/host boundary. Whole-app adoption would conflict with Captain's single user-facing control-plane.
- Maintenance/status: active early preview; Windows/Linux qualification and stronger plugin sandbox are still in progress.
- Resource cost: likely moderate (Electron + Rust host + Node sidecar); benchmark before any reuse.
- Decision: inspect workbench/preview/permission boundary patterns only; no installation until license/dependency/security audit is complete.
- Source: https://github.com/vastsa/PI-Desktop

### Modus
- Capability: Apache-2.0 local-first coding-agent workspace using Monaco, xterm.js, Electron/React and a Rust PTY layer; project/session separation, diff review, MCP config and BYO models.
- Fit: medium-high for reusable builder-pane UX patterns/components. Do not adopt its provider/router layer because Captain already owns the primary router/control-plane.
- Resource cost: moderate Electron + Rust/Node stack; needs Windows laptop profiling.
- Decision: candidate for UI/terminal/diff patterns after source and dependency audit, not a full subsystem yet.
- Source: https://github.com/brandlll-lee/modus

### OpenChamber
- Capability: open-source agentic development workspace for running, supervising and reviewing coding work across desktop/browser/editor/mobile, with persistent project context and review-oriented workflow.
- Fit: medium-high as architecture/UX reference for Captain's builder pane, task supervision and cross-device review. Whole-app adoption would conflict with Captain remaining the single user-facing orchestrator.
- Maintenance/status: actively presented upstream as a current project; source/dependency/license details still need a focused audit before any reuse.
- Resource cost: unknown until dependency inspection; do not install on the laptop before profiling.
- Decision: inspect pane/session/review boundaries and reuse only narrow components or patterns if licensing/security fit.
- Source: https://github.com/openchamber/openchamber

### Awesome AI Agent Incidents
- Capability: MIT curated corpus of real-world autonomous-agent incidents, attack vectors, CVEs, failure modes and defensive tooling.
- Fit: high as an evaluation/red-team corpus, not as a runtime subsystem.
- Security value: can seed Captain regression scenarios for prompt-injection, secret exfiltration, unsafe tool delegation and confused-deputy failures without adding another control-plane.
- Resource cost: negligible if consumed as curated test cases/documentation.
- Decision: prioritize a small reviewed subset into Captain's adversarial eval suite after mapping every case to a deterministic local test; never execute exploit payloads blindly.
- Source: https://github.com/h5i-dev/awesome-ai-agent-incidents

### AgentAuth
- Capability: MIT capability-based agent authorization with explicit human approval, short-lived grants and per-call verification.
- Fit: medium-high as reference for Captain's permission-grant lifecycle and revocation semantics, not as a separate registry/verifier daemon stack.
- Security value: reinforces explicit grants rather than treating declared permissions as approved permissions.
- Resource cost: full stack is too heavy for Captain's laptop-first single-control-plane goal; reuse protocol/crypto ideas only after audit.
- Decision: reference/adapt concepts, do not install or run the full stack.
- Source: https://github.com/maxmalkin/AgentAuth

### Multicorn Shield
- Capability: MIT policy/consent layer for agent permissions, spending limits and tamper-evident audit logging.
- Fit: medium as policy/evaluation reference; whole-product integration would add a competing control/dashboard layer.
- Security value: consent, scoped access and spend controls map well to Captain Settings and observability requirements.
- Resource cost: Node/pnpm SDK layer is plausible, but external dashboard/control semantics conflict with Captain being canonical.
- Decision: inspect policy and audit patterns only; no proxy/control-plane adoption.
- Source: https://github.com/Multicorn-AI/multicorn-shield

### MCP 2026-07-28 authorization changes
- Capability: current MCP guidance adds authorization-server issuer validation and desktop/CLI Dynamic Client Registration metadata improvements.
- Fit: high for Captain OAuth connector-health/version checks and migration diagnostics.
- Decision: treat issuer validation and auth-spec version compatibility as future connector acceptance requirements.
- Source: https://blog.modelcontextprotocol.io/posts/2026-07-28/

### agent-intern
- Capability: MIT MCP server delegating to official Codex/Copilot/Cursor/Gemini CLIs under existing user logins, with fan-out and watch UI.
- Fit: low as a whole subsystem because it would duplicate Captain orchestration/model routing; medium as reference for thin CLI adapters and independent QA delegation.
- Security/auth note: never copy or discover credentials, never silently install CLIs, and never rely on ambient login reuse without an explicit connector state/permission contract in Captain Settings.
- Decision: reference only; no install/execute.
- Source: https://www.reddit.com/r/mcp/comments/1uv9fok/i_built_an_mcp_server_that_lets_claude_code/

### Continue (archived/read-only upstream)
- Capability: Apache-2.0 coding-agent foundation across CLI/VS Code/JetBrains.
- Fit: low for new direct integration because the main upstream repository now states it is read-only/no longer actively maintained.
- Decision: do not adopt as a new Captain dependency; historical patterns may be referenced only when still relevant.
- Source: https://github.com/continuedev/continue
