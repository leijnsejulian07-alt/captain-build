# Captain OSS scout — 2026-09-01

Scope: fresh scan only; no third-party code was installed or executed.

## Nightona
- Source: `nightona-co/nightona`, community continuation of Daytona's last open release.
- Capability: self-hosted isolated agent sandboxes, OCI/Docker compatibility, per-sandbox filesystem/network/kernel/resource isolation, SDK/API/CLI, snapshots.
- License/maintenance: AGPL-3.0 community fork of Daytona v0.190.0 after Daytona moved current core development private in June 2026.
- Captain fit: useful architectural reference or optional external sandbox adapter, but AGPL obligations and a relatively heavy runtime make direct bundling unattractive for the laptop-first default.
- Decision: reference/optional adapter only; do not embed in Captain core.

## OpenHands software-agent SDK
- Capability: mature coding-agent/sandbox separation and agent-server architecture with multiple runtime environments.
- Current risk signal: an open June 2026 issue reports Chromium/browser-use launch failures in the published agent-server Docker image; a May 2026 feature request also highlights missing pluggable durable execution for long-running tasks.
- Captain fit: good interface/lifecycle reference, but not a drop-in runtime until browser and durable-job behavior meet Captain acceptance gates.
- Decision: study adapters and lifecycle contracts; no install.

## sandbase-harness
- Capability: local-first sandboxed agent sessions, MCP bridge, credentials isolation, audit/replay and console; release images advertise OCI source/provenance metadata.
- Captain fit: potentially useful optional sandbox/MCP execution subsystem because it can remain behind Captain's control-plane rather than becoming the orchestrator.
- Risks: another runtime service/daemon and Docker resource cost; auth/credential boundary needs independent review before use.
- Decision: promising candidate for later adapter evaluation, not integration yet.

## Community signal
Recent Reddit discussions continue to converge on two practical controls relevant to Captain: Git worktrees alone are not a sufficient security boundary, and autonomous coding agents benefit from sandbox/network isolation plus explicit test/diff/review gates. Community reports also warn that coding agents without confinement may modify files outside the intended workspace. Treat these as experience reports rather than authoritative security evidence.

## Priority
No candidate justifies replacing Captain's existing single router/control-plane. Highest-value near-term work remains fail-closed promotion/validation evidence and resource isolation. If a sandbox subsystem is later added, prefer a thin adapter with explicit per-project permissions, bounded resource cost, no secret copying, and a default-off install path in Captain Settings.
